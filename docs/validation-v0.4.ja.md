# v0.4 検証記録

実施日：2026年10月1日（日本時間）。対象はM-Anchor Appのローカル試作版。研究用の正式評価とは別の記録である。

## 結果

Linux / Python 3.12で34件の自動テストが通過した（15.934秒）。実行ログは[tests](validation-v0.4-tests.txt)。UIの実JavaScriptを最小限のDOM代替と実HTTPサーバーで動かす確認も通過した（[UIログ](validation-v0.4-ui.txt)）。

モデル応答はテスト内で置き換えている。モデル経路の記録保持を検査したもので、実モデルの生成品質を検査したものではない。有料API呼出しは行っていない。

| 確認対象 | 方法と結果 |
| --- | --- |
| 保存・拒否・変更なし | 従来の状態、version、hash、証拠認可のテストが通過 |
| 実行情報の永続化 | 模擬モデルによる更新後、別の固定デモを実行し、HTTPサーバーを停止・再生成。元のモデル情報・原文・判定・再読込結果がJSONに残ることを確認 |
| 判定との対応 | 同一提案の繰返しも別idで記録。並行提出で保存一件と拒否一件がそれぞれの実行記録に結び付く |

| 提出経路 | 固定デモ・手動・クライアントAPIを区別。agentキーでは管理経路を呼べず、任意のヘッダーでモデル経路を自己申告できない |

## 判定処理への変更範囲

GateのStoreに実行情報の表と同時保存を追加し、応答にaudit_idを追加した。Gate全体のファイルは変更されている。提案の解釈、証拠認可の検査、候補の遷移を担う `_parse_proposal`、`_validate_authority`、`_evaluate` の構文木が従来と一致することを確認した。

形式核 `app/vendor/python_v0.1/m_anchor_minimal.py` のSHA256は従来と同じ `0f9551e8d00cd4408441944d9067cfe9bce7d5653019a5af27738fb5895f58c9`。

## 未確認・対象外

- 利用者のWindows環境でのv0.4起動、実ブラウザの描画、実APIでの新しい記録。この版の自動確認はLinux上で行った。
- 旧版移行テストは旧スキーマを再現したもので、利用者の実DBを直接操作したものではない。
- 署名による出所証明、改ざん耐性、OS権限で直接DBを書き換えるプログラムからの隔離。
- 大量履歴の負荷試験、電源断・媒体故障の試験。故障注入はSQLエラーと再読込未記録状態を対象とした。
- モデル応答を得る前のAPI失敗は、提案が存在しないため判定履歴には残さない。
- GitHub ActionsでのCI実行、AWSでの配備・常時運用は今回実施していない。
