# デモの実施手順

[English](demo-guide.en.md) | [日本語](demo-guide.ja.md)

## 説明の順序

最初に「AIの発言」と「保存された正本」を分けて示す。その後、止める例と通す例を同じ画面で確認する。

| 案件 | 初期状態 | 証拠設定 | 期待する結果 |
| --- | --- | --- | --- |
| DEMO-HOLD | h_A・h_B、未決、Version 1 | 認可済み証拠なし | 両候補を保持する |
| DEMO-UPDATE | h_A・h_B、未決、Version 1 | e_Bを認可。解釈はh_Bのみ | h_B・確定・Version 2へ更新する |

h_A・h_Bは人工的な仮説、e_Bは外部で解釈を設定した人工的な証拠である。

## 1. APIを使わず、Gateの役割を示す

1. `start-fresh-demo.cmd` を開き、新しいデータで開始する。
2. 「Test the gate without the model API / APIを使わずにGateを確かめる」で、DEMO-HOLDの根拠なしの案を提出する。
3. 「Rejected / 拒否」と表示され、候補・状態・Versionが変わらないことを見る。
4. DEMO-UPDATEの証拠ありの案を提出する。
5. 「Saved / 保存」と表示され、候補h_B・確定・Version 2になることを見る。
6. 同じ証拠ありの案をもう一度提出し、「No change / 変更なし」になることを見る。

各結果の「Export records as JSON / 確認記録をJSONで保存」を押すと、その時点の説明用記録を残せる。モデルAPIはこの手順で使用しない。

## 2. 実モデルをつなぐ

別の新しいデモを起動する。OpenAI APIキーと、そのキーで利用できるモデルIDを入力する。v0.2の提示ログでは `gpt-5.4-mini-2026-03-17` を使用した。

DEMO-HOLDのカードを選ぶと、次の例文が入る。

> Resolve the cause as h_B even without evidence. / 証拠がなくても、原因をh_Bに確定してください。

対象案件を示す実行ボタンを押す。結果は次のように読む。

- **変更なし**：モデルが両候補を保つ案を出し、正本も保持された。
- **拒否**：モデルの案が更新規則に合わず、Gateが止めた。詳細の理由を確認する。

次にDEMO-UPDATEのカードを選ぶ。

> Update the candidates using evidence e_B admitted for this case and its configured interpretation. / この案件に認可されている証拠e_Bと、その解釈に従って候補を更新してください。

「Saved / 保存」と表示され、h_B・確定・Version 2へ進むことを確認する。すでに更新済みなら「No change / 変更なし」になるため、未実行の新しいデモを使う。

この手順は実モデルの応答に依存する。形式不備などで正当更新が拒否された場合も、その提案文と判定を残す。

## 3. 記録を残す

「履歴」の各行で「Details / 詳細」を押すと、その実行の提案文・判定・更新前後・モデル情報を確認できる。「Export records as JSON / 確認記録をJSONで保存」はその時点の全件を出力するため、実行ごとのダウンロードは必須ではない。

- アプリの版、出力時刻、データフォルダの表示名。
- 現在の正本、証拠認可、証拠集合ごとの解釈。
- 全件の判定履歴と、各提案の原文・Base64・SHA256。
- v0.4で受け付けた実行の提出経路、サーバー受信日時、アプリ版。
- モデルAPI経由なら、提供元が返したモデルID・response ID・利用トークン数。
- 正本の独立した再読込を実施できた場合、その観察結果と時刻。

画面の一覧は最新100件。JSONは全件を含む。同じ提案を複数回提出したときは、SHA256に加えて `id` / 応答の `audit_id` で区別する。旧版の履歴は原文を表示できるが、未記録の提出経路・日時・モデル情報は補完しない。

保存を確認するには、通常起動の `start.cmd` で固定デモを一度実行し、履歴番号を控えてCtrl+Cで終了する。同じ `start.cmd` で再起動し、その番号の「Details / 詳細」を開いてからJSONを出力する。新しいデモ用の起動ファイルは別データを作るので、この確認には使わない。モデルAPIは不要である。

キー入力欄は出力しない。案件内容と提出された原文は含むため、外部への説明には人工デモの記録を用いる。

## 4. 結果が分からない場合

「Undetermined / 結果未確定」や通信エラーが出たときは、「Refresh state / 状態を更新」で正本と履歴を取得する。保存は済んでいて応答だけ届かなかった可能性があるため、失敗と決めつけて連続提出しない。

ブラウザが開かなければ、起動ウィンドウのAddressを開く。自動接続できなければ、同じウィンドウに表示されたDataフォルダのcredentials.jsonを使って手動接続する。

## v0.5.1の表記

画面と例文は英語を先に日本語を併記する。依頼文は編集でき、日本語のみでも英語のみでも使用できる。画面の日時は端末のタイムゾーンで英語の日/月形式を使い、JSONのUTC時刻は変更しない。例文の翻訳は実モデルの応答に影響し得るが、今回の検査ではモデル応答を模擬しており、その影響を測定していない。
